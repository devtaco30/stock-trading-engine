# 스테이트풀 엔진 HA — K8s StatefulSet + PV, 확장은 복제가 아니라 샤딩

## ADR 네타
### ADR-026 스테이트풀 엔진 HA = K8s StatefulSet + PV (노드 장애 내구성은 스토리지층)
- **context(무슨 상황)**: 로컬 디스크 저널은 프로세스 크래시만 생존한다. 노드(파드가 도는 서버)가 죽으면 로컬 디스크가 노드와 함께 소멸한다. Jack이 제기했다 — HA 없는 설계가 효용이 있느냐([[규모 프레임 금지]] 재위반), 그리고 노드가 내 서버가 아니라 쿠버네티스/도커 아니냐.
- **왜(문제·동기)**: 노드 = 파드가 도는 서버. 노드 장애를 버티려면 저널이 노드 밖에 있어야 한다. 로컬 디스크는 노드와 함께 죽는다.
- **어떻게(대안·결정·트레이드오프)**: K8s StatefulSet(안정 신원 + 파드별 PV)을 쓰고, Archive 저널을 네트워크 PersistentVolume(EBS류)에 둔다. 노드가 죽어도 PV가 살아서 다른 노드에 재스케줄 + PV 재연결 + replay로 복구한다. 노드 장애 내구성은 스토리지(PV)층이 담당하고 앱 복제 없이도 성립한다. 앱 레벨 복제(Aeron Cluster/Archive replication)는 초 이하 페일오버가 필요할 때만 쓴다(ADR-019의 Cluster 기각과 정합). 대가는 PV가 네트워크 I/O라 로컬보다 느리다는 것이다.
- **무엇을(실제 변경·파일·커밋)**: 지금 코드는 거의 안 바뀐다 — 결정론(ADR-023 갱신) + 저널(ADR-025) + 리플레이가 토대이고, K8s는 배포 형태(Archive dir = PV 마운트) + 파드 재시작 replay다. 2b-2를 "파드 재시작 복구 = 팔로워 가능"으로 설계했다. 실제 컨테이너화·다중 노드·복제는 명시적인 뒤 단계다(한 머신에서 Archive 2개로 시뮬 검증 가능).
- **결과·수치**: PV는 네트워크 I/O라 로컬보다 느리다. 복구 시간 = PV 재연결 + replay(수 초). 초 이하가 필요하면 웜 스탠바이(앱 복제)가 있어야 한다. 노드 장애 생존 경계 = PV까지 실제 flush된 지점(페이지캐시는 노드 RAM이라 노드와 함께 죽는다).

## 블로그 네타
### "스테이트풀 엔진의 HA는 앱이 아니라 K8s가 — StatefulSet + PV"
- **훅·핵심 주장**: 로컬 디스크 저널은 노드가 죽으면 같이 죽는다. 스테이트풀 엔진의 고가용성은 앱을 복제해서가 아니라 저널을 노드 밖 PV에 두고 K8s가 재스케줄·재연결하게 해서 얻는다.
- **context**: 로컬 저널이 프로세스 크래시만 버틴다는 한계. "노드가 내 서버냐 쿠버네티스냐"는 질문에서 나옴.
- **어떻게(서사·근거)**: 노드 = 파드 도는 서버. StatefulSet(안정 신원 + 파드별 PV), Archive 저널을 네트워크 PV에. 노드 죽어도 PV 생존 → 재스케줄 + 재연결 + replay. 노드 장애 내구성 = 스토리지층. 앱 복제(Aeron Cluster)는 초 이하 페일오버 때만. 결정론 + 저널 + 리플레이가 이미 토대라 코드는 거의 안 바뀜.
- **재료(커밋·도식·수치)**: 복구 시간 수 초(PV 재연결 + replay). 생존 경계 = PV flush 지점. 한 머신 Archive 2개로 시뮬 가능.

### "스테이트풀 엔진 확장은 복제가 아니라 샤딩"
- **훅·핵심 주장**: stateless 서비스는 복제본을 늘려 확장하지만, single-writer 엔진은 복제하면 쓰기 주인이 둘이 되어 정합성이 붕괴한다. 그래서 키로 샤드를 나눈다(accountId/stockCode). 샤드 하나의 HA는 복제가 아니라 PV + replay다.
- **context**: 대용량 + HA 전제. api는 stateless라 복제 N개(아무나 받음), 계좌·매칭은 single-writer.
- **어떻게(서사·근거)**: single-writer를 복제하면 쓰기 주인 둘 = 정합성 붕괴 → 키로 샤드 분할. 샤드 HA = PV + replay(복제 아님). 규모가 커질수록 노드 장애 빈도↑ → HA 필수. 남은 대용량 난제 = 두 경로 정렬(공유 맵)·동적 리샤딩(상태 이동).
- **재료(커밋·도식·수치)**: 도식 `docs/_k8s_full_pipeline_ha.html`(핫패스/오프패스/노드장애 3장)·`docs/_k8s_ha_topology.html`.
