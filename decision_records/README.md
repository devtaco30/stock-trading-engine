# 작업 기록 (decision records)

작업 단위를 하나 끝낼 때마다 그 자리에서 남긴 기록이다. 무엇이 문제였고, 어떤 안을 놓고 견줬고, 왜 그걸 골랐고, 실제로 어느 파일·커밋이 바뀌었는지를 적는다. 지금 54개 있다.

파일 앞에는 `feature · date · branch · commits` 네 줄이 있고, 본문은 `왜(문제·동기) / 어떻게(대안·결정·트레이드오프) / 무엇을(실제 변경·파일·커밋) / 결과·수치` 순서로 쓴다.

## `adr/`와 무엇이 다른가

`adr/`은 결정을 정리해 둔 문서다. 문제·대안·트레이드오프·결정·결과 형식으로 다듬고, 그 사이에 폐기된 시도나 세션 사정은 덜어낸다.

이 폴더는 그 전 단계다. 측정값, 커밋 해시, 확인하지 못한 채 남긴 항목, 판단을 뒤집은 지점이 다듬지 않은 상태로 남아 있다. 같은 주제를 두 번 적은 파일도 있다 — 뒤 파일이 앞 파일의 결론을 고친 경우다(예: `account-idempotency-cache-bound.md` → `tradeid-snapshot-prune.md`).

여기 있는 기록 중 열 개가 `adr/`로 올라갔고, 해당 ADR의 `관련` 줄에 원문 파일 이름이 적혀 있다. 나머지는 아직 이 폴더에만 있다.

## 파일 안의 괄호 별명

본문에 `(39)`·`(2b)` 같은 표기가 나오면 그 작업을 한 세션을 가리킨다. 이 프로젝트는 여러 세션을 동시에 돌리면서 설계·구현·측정을 나눠 맡겼고, 기록에 그 흔적이 남았다.

| 별명 | 역할 |
|---|---|
| 39 | 설계와 리뷰. 다른 세션의 판단을 되짚어 지적한 자리에 자주 나온다 |
| 2b | 세션 간 조율, 산출물 검토 |
| dc | 부하 측정과 측정 하네스 |
| ec | 자원 관리(스레드·디스크)와 전송 유실 설계 |
| a4 | 세션 인수인계 정리 |

`coordination-*.md`와 `dc-handoff-*.md`에는 결정 대신 그 조율·인수인계 내용이 들어 있다.
