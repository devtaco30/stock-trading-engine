# 기준선 재측정 프로토콜 (묶음 B 단계 1)

**임시값, Jack 확정 전.** 아래 숫자(30%, 40%, 25%, 연속 2개, 유효 회차 7개 미만)는 설계서 `lld-B-measurement.md` 2-3절의 값을 그대로 옮긴 것이다. 임의로 정한 값이고 데이터에서 도출하지 않았다. Jack이 바꾸면 이 표만 바꿔 다시 고정한다.

고정 방법: 첫 회차를 시작하기 전에 이 문서를 커밋하고, 그 커밋 해시와 파일의 SHA-256을 결과 디렉터리의 `protocol.sha256`과 `env.txt`에 기록한다. 결과를 본 뒤에는 이 문서를 고치지 않는다.

측정 대상 코드는 `origin/main` = `ee55642fc3b045189f6b1b37fdb5fb5b5d1e6f5f`다. 조건은 v1과 v2 두 개이고, 조건마다 JVM을 한 번만 기동해 `r01`~`r11` 11회를 재기동 없이 연속으로 보낸다. 회차 하나는 주문 1만 건(`N=10000`)을 초당 192건(`RATE=192`)으로 보내는 한 바퀴다.

## 제외 규칙

회차 제외는 아래 네 규칙에만 따른다.

1. **환경 문제가 기록된 회차**만 제외한다. 환경 문제의 판정은 아래 E1~E6의 숫자로만 한다.
2. **첫 회차(`r01`)는 값과 무관하게 워밍업으로 제외한다.**
3. **값이 크다는 이유로는 제외하지 않는다.** p99가 앞뒤 회차보다 얼마나 크든 제외 사유가 아니다.
4. **회차 건수가 1만이 아닌 회차**(히스토그램 count ≠ 10000 또는 v1 DB 증가분 ≠ 10000)는 측정 불성립으로 제외한다. 이것은 값의 크기와 무관한 정합성 검사이므로 규칙 3과 부딪히지 않는다.

## 환경 문제 판정 기준

회차마다 k6가 도는 구간 `[k6 시작, k6 종료]` 안의 샘플로 판정한다.

| 코드 | 판정 | 기준 | 근거 |
|---|---|---|---|
| E1 | 전체 CPU 포화 | 전체 idle%가 30% 미만인 샘플이 연속 2개 이상 | 이전 B-2에서 tail latency(가장 느린 요청들의 응답 시간)가 오염된 구간의 idle이 11~26%였다(`numbers.md` §6). 30%는 그보다 위로 잡은 임의값이다 |
| E2 | 부하 생성기 경쟁 | k6 프로세스 CPU가 1코어 대비 40% 이상인 샘플이 연속 2개 이상 | B-2에서 오염된 구간의 k6가 54~69%였다. 초당 192건에서 k6의 값은 이전에 측정한 적이 없다 |
| E3 | 전력·열 | 전원이 배터리로 바뀌었거나(`pmset -g batt`), CPU 속도 제한이 100 미만(`pmset -g therm`)인 샘플이 1개라도 있음 | 임의값 |
| E4 | 외부 부하 | top 상위 5개 프로세스 중 허용 목록(`k6`, `java`, Docker 관련 프로세스, `kernel_task`)에 없는 프로세스가 CPU 25% 이상으로 연속 2개 샘플에 나타남 | 임의값. 허용 목록은 첫 리허설에서 실제 top 출력을 보고 확정한다 |
| E5 | 부하 생성 이상 | k6 종료 코드 ≠ 0, 또는 요약 JSON의 `checks` 실패 ≥ 1, `http_req_failed` 발생 ≥ 1, `dropped_iterations` ≥ 1 | `numbers.md` §8: 원본 JSON에서 `http_req_failed.passes`가 실패 수, `fails`가 성공 수로 읽혔다. 첫 리허설에서 한 회차로 필드 의미를 확인한다 |
| E6 | 컨슈머 재배정 | (v1만) order-engine 또는 matching-engine 로그에서 구간 안에 파티션 재배정(rebalance) 기록이 있음. matching-engine은 main에서 파티션을 배정받을 때마다 DB 조회가 일어난다 | 로그 문구는 아직 확인하지 못했다. 리허설에서 실제 문구를 확인한 뒤 고정한다 |
| E7 | 프로세스 사망 | 앱 JVM이 구간 안에 종료됨 | 이 경우 회차를 제외하지 않고 조건을 중단한다(아래) |

## 추가 사전 선언

- 한 조건에서 유효 회차(제외되지 않은 측정 회차)가 7개 미만이면 그 조건은 "측정 불성립"으로 선언하고 전체 조건을 처음부터 다시 돈다. 재실행은 조건당 1회까지고, 첫 번째 세트의 결과도 보고서에 남긴다.
- 제외된 회차의 값도 결과 표에 그대로 싣는다(제외 사유 코드와 함께). 결과는 "규칙을 적용한 표"와 "11회 전부의 표" 둘을 같이 낸다.
- 조건 중단(E7): 앱이 죽으면 그 조건은 중단하고 처음부터 다시 돈다. 중단 시점까지의 파일은 지우지 않는다.
